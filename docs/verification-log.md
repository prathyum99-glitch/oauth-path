# Verification log

What was checked against real sources, what that taught, what was corrected, and what could not be verified. Dates are 2026-11-01 unless noted. Seed guides were read through a summarising fetch tool, not raw page text, so every seed claim ships as **not re-checked**. `npm run verify-seeds` has the independent verifier agent re-read the cited pages and record real statuses.

## Learned from the sources

| # | Finding | Why it matters |
|---|---|---|
| 1 | Composio's docs contradict themselves on managed auth. One page says every OAuth toolkit has a managed app. The managed-auth page says to check each toolkit's `composio_managed_auth_schemes` field. | The product reads the per-toolkit field and never assumes. |
| 2 | Google gives two figures for sensitive-scope review: "up to 10 days" (scope page) and "about 10 business days" (FAQ). Restricted: "several weeks" vs "about 6 weeks". The FAQ says estimates are not guaranteed. | The Gmail guide uses the longer reading (about two weeks of calendar time) and says so. |
| 3 | Google's verification overview omits the steps, the 100-user cap and the CASA security assessment. They live on four other pages. | A guide built from the overview alone would call Gmail easy. |
| 4 | Slack's rule of at least 10 active installs before Marketplace submission appears only in a 2026-09-01 changelog, not on the distribution guide. | Older write-ups and the main guide page are already out of date. |
| 5 | Slack publishes no Marketplace review time, only a 2 business day support reply time. | The wait shows "No review time published", not a guess. |
| 6 | Notion's authorization page says the authorization URL appears after the connection is submitted for review, and never says whether approval is required. | Left as an open question in the Notion guide. A person creating a connection would settle it in minutes. |
| 7 | LinkedIn's access pages list which permissions are open and which need approval. They say nothing about creating the app or Page-admin verification, and give no review time. | The LinkedIn guide marks app creation as unverified. |

## Could not be verified

- **Reddit's Responsible Builder Policy** page could not be fetched (client error). Approval details for Reddit are unverified, and the wiki says parts of itself are outdated.
- **Intuit (QuickBooks) developer docs** render in the browser, so the fetcher cannot read them. QuickBooks is the stress test for live generation: expect secondary sources and a lot of "unverified".
- **CASA assessment cost** (Google) is not stated on any page read.
- **Whether test or internal workspaces count** toward Slack's 10 installs is not stated.
- **Notion access token lifetime** is not stated on the pages read.
- **LinkedIn app creation and Company Page requirements** are not covered by the pages read.
- **No setup was run by hand.** Every guide shows "Tested by a person: No". A 20 minute Discord Developer Portal run and a Notion public-connection creation are the cheapest ways to earn a real "tested" label.
- **The live pipeline has not been run against the real model** in the build sandbox, which had no API key. It is tested end to end against a scripted model (`tests/pipeline.test.ts`). `npm run smoke -- "QuickBooks"` runs it for real.

## Second pass: spot-check of five high-stakes pages (2026-11-01, after the first build)

Re-read through a summarising fetch tool, asking for exact numbers and for what each page does *not* say. This is not the independent verifier agent (that needs an API key), so seed claims stay "not re-checked".

| Page | Result |
|---|---|
| Slack Marketplace install requirement | **Confirmed**: at least 10 installs on active workspaces, kept through review. **Tightened**: the page says "as of July 2026" (the post is dated 2026-09-01), says it is "up from a temporary lower threshold", and does not define an active workspace. Guide updated. |
| Google OAuth verification FAQ | **Confirmed**: 100 new-user lifetime cap that cannot be reset; sensitive 10 business days; restricted 6 weeks; brand verification 2 to 3 business days; estimates not guaranteed. No change. |
| Notion Marketplace FAQ | **Corrected**: the page says to "expect to hear back" in 5 to 10 business days. It does not say whether that is a decision or a first reply. The guide had called it a "review" time. Wording fixed in the headline, wait label, claim and step. Listing optional and Any-workspace scope required: confirmed. |
| LinkedIn authorization code flow | **Confirmed**: 30 minute code, 60 day access token, programmatic refresh limited to partners, https absolute redirect URLs without fragments. **Not stated**: refresh token lifetime, whether localhost redirects are allowed. No change. |
| Reddit Data API wiki | **Corrected**: the page gives 100 queries per minute per OAuth client ID (10 without OAuth, 10 minute window) with a July 1, 2023 effective date, and does not mention free-tier eligibility, so the guide no longer says "free-tier eligible". Added the User-Agent format. Confirmed again: the page does not explain how to register an app. |

Net effect of the pass: two wording corrections that would have overstated what a provider said (Notion, Reddit), one added caveat (Slack), and no wrong numbers found among the figures checked.

## First live runs on the deployed site (2026-11-01)

The agent ran against the real model for the first time on the Vercel deployment. Two apps, one by name and one by website, each saved a shareable guide.

| Run | Input | Outcome |
|---|---|---|
| QuickBooks | `QuickBooks` | Moderate. 26 claims: 24 official, 1 inferred, 1 unverified. 24 re-read by the second agent; 23 confirmed, 1 partly confirmed. Three Intuit pages that only appeared as search snippets were listed as "could not be read" and used for nothing. Token lifetimes were left in "could not be confirmed". |
| Calendly | `calendly.com` | Easy. 27 claims: 24 official, 3 inferred. 24 re-read; 22 confirmed, 2 partly confirmed (the second agent said Calendly's page does not say native apps omit the secret). A partner page returned 404 and was reported as such. It took about two minutes. |

What reading the output turned up, and what changed:

- **Misleading label.** The "Weakest support behind this verdict" line listed every claim the verdict cited under the weakest label. For QuickBooks that put confirmed claims c1, c3, c5 and c6 next to "Unverified", when only c21 was. It now lists only the claims at the weakest level.
- **Overclaiming grade text.** The Easy grade said "Usually under a day, no review" on every Easy guide. Calendly's own docs say new apps get scopes only once "requested and approved", and Notion's approval step is unresolved. The text now says the pages read describe no approval step and points to what is unconfirmed.
- **Not yet shown.** Composio managed-auth status reads "not checked" on both runs because no `COMPOSIO_API_KEY` is set on the deployment.
- **Not yet done.** Neither guide has been run by hand, so both say "Tested by a person: No".

### Composio lookup, second pass (2026-11-01)

With a `COMPOSIO_API_KEY` set on the deployment, the Calendly run showed "Composio API answered HTTP 401": the key was refused, and the guide said so rather than guessing. Reading the code for that case turned up a second problem: the lookup turned "QuickBooks Online (Intuit Developer)" into one long toolkit name, which Composio would not recognise. The lookup now tries the name without brackets, then the first word, then the full name; trims the key; sends `uak_` user keys in their own header; and names the matched toolkit in its note. Seven new tests cover this.

### Composio check confirmed, and a billing failure found (2026-11-01)

With a fresh project key, the Calendly guide now reads: Composio toolkit "calendly" provides the OAuth app (OAUTH2). A QuickBooks re-run then failed with a vague message. The Vercel runtime log showed the cause: the Anthropic account was out of credit ("credit balance is too low"), not a bug in the pipeline. The app now says this in plain words, and also says when the model key is rejected. The QuickBooks long-name slug fix has not yet been seen on a live run for that reason.
